## Key Findings (Architecture Analysis)

### Throne Architecture Summary
- **Language:** C++20, Qt 6 (Widgets)
- **Build:** CMake 3.20+, Ninja/MSVC
- **Database:** SQLite via SQLiteCpp (`throne.db`)
- **Core:** sing-box primary, Xray for Xray-specific configs
- **RPC:** Protobuf over local sockets (QLocalSocket)
- **Process:** Single CoreProcess (QProcess) with auto-restart
- **Config Generation:** Massive `generate.cpp` builds sing-box/Xray JSON
- **Data Model:** Settings (KV), Groups, Profiles, Routes, IpLists
- **Single-Instance:** QLocalServer with config-dir hash name

### Critical Integration Points for Multi-Instance
1. **CoreProcess** → Refactor for multiple simultaneous processes
2. **RPC Client** → Pool for multiple socket connections
3. **Database** → Add `instances` table, `instance_id` FK on `groups`
4. **Config Generation** → Per-Instance, CoreAdapter-routed
5. **Settings** → Split global vs per-Instance (`instance_settings` table)
6. **Ports** → Central PortAllocator with bind-time verification
7. **UI** → Instance selector, per-Instance dashboard
